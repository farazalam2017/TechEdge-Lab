## Short Notes: AI Models & Open Source

### 1. Open Model vs Closed Model

| Open Model                                                                  | Closed Model                                             |
| --------------------------------------------------------------------------- | -------------------------------------------------------- |
| Model weights/code may be publicly available.                               | Model weights/code are generally not publicly available. |
| Developers can download, modify, or run it depending on its license.        | Users mainly access it through an API or application.    |
| More control and customization.                                             | Easier to use but less control.                          |
| Examples: Llama, Mistral, Qwen (depending on the specific release/license). | Examples: GPT, Claude, Gemini.                           |

**Simple example:**  
Open model = _You can get the machine and study/modify it._  
Closed model = _You can use the machine, but the internal design is controlled by the company._

> **Important:** “Open source,” “open weights,” and “open model” are not always exactly the same. Always check the model's license and what has actually been released.

---

### 2. Open-Source Repository

An **open-source repository** is a place where source code is publicly available so people can inspect, use, contribute to, and sometimes modify it according to its license.

**Example:** [Microsoft VS Code GitHub Repository](https://github.com/microsoft/vscode?utm_source=chatgpt.com)

Students can explore:

- Source code
- Issues
- Pull requests
- Contributors
- Releases
- Documentation

**Real-world idea:** A student can find a bug → fix it → create a Pull Request → maintainers may review and merge it.

---

### 3. Closed-Source Repository

A **closed-source repository** contains source code that is not publicly available.

The company internally controls:

- Source code
- Development
- Security
- Updates
- Architecture

Users can normally **use the software without seeing its complete source code**.

**Example:** The internal source code of many commercial AI systems is not publicly released.

---

## 4. AI Models Based on Size

AI models can be broadly discussed in terms of their **number of parameters, computational requirements, and intended use**.

### A. Edge Models

Small models designed to run on:

- Mobile phones
- Laptops
- IoT devices
- Edge devices

**Advantages:**

- Fast response
- Lower hardware requirements
- Can work with limited/no internet
- Better privacy for some applications

**Example use:** AI keyboard, phone assistant, camera object detection.

---

### B. Standard / Open Models

Medium-sized models that can be run by developers or organizations using suitable hardware/cloud infrastructure.

They can be useful for:

- Chatbots
- Coding
- Text generation
- RAG applications
- Educational applications

Examples include various releases from **Llama, Qwen, Mistral**, etc.

---

### C. Frontier Models

Very large and highly capable models developed using enormous amounts of:

- Data
- Computing power
- Training time
- Specialized hardware

They are designed for demanding tasks such as:

- Advanced reasoning
- Coding
- Multimodal understanding
- Complex research and problem solving

Examples include leading models from companies such as OpenAI, Google, and Anthropic.

### Easy way to remember

**Edge → Small & Local**  
↓  
**Standard → General & Deployable**  
↓  
**Frontier → Very Large & Highly Capable**

> **Note:** There is no universal parameter-count cutoff that officially defines “edge,” “standard,” or “frontier.” Model capability depends on much more than parameter count.

## 5. Cal.com

[Cal.com](https://cal.com/?utm_source=chatgpt.com)

**Cal.com** is an open-source scheduling platform.

It allows people to:

- Create booking pages
- Share availability
- Schedule meetings
- Connect calendars
- Integrate scheduling into applications

**Interesting point for students:**  
It demonstrates how an open-source project can become a real-world technology product.

---

## 6. Google Summer of Code (GSoC)

[Google Summer of Code](https://summerofcode.withgoogle.com/?utm_source=chatgpt.com)

**Google Summer of Code (GSoC)** is a program where contributors work with open-source organizations on real projects.

Students can learn:

- Git & GitHub
- Open-source contribution
- Software development
- Collaboration
- Professional coding practices

**Typical journey:**

`Find Project → Study Repository → Discuss Idea → Apply → Code → Get Reviewed → Contribute`

---

## 7. Why GitHub Is Important for BCA Students

GitHub is more than a place to upload code.

Students can use it to:

**Learn → Build → Collaborate → Contribute → Show Portfolio**

For example:

`Learn React`  
↓  
`Build Project`  
↓  
`Upload to GitHub`  
↓  
`Contribute to Open Source`  
↓  
`Build GitHub Profile`  
↓  
`Show Work to Recruiters`

### One-line takeaway

> **The future developer is not only someone who can write code, but someone who can understand existing code, use AI tools, collaborate through GitHub, and contribute to real software projects.**
